# 架构与权限

`app/` 是普通用户的 AppKit / SwiftUI 应用。它只读 root 后台导出的 JSON 状态，通过本地 Unix socket 发送固定的启用 / 关闭命令。后台使用 `getpeereid` 核对当前控制台用户，不接受任意命令、路径或 shell 字符串。

“重新连接 LTE”使用同样受限的固定 `R` 请求，仅允许当前控制台用户在 LTE 已启用时操作。助手核对本项目 supervisor 的进程身份后发送 SIGUSR2，supervisor 先关闭旧会话及其 utun，再开启新的控制会话；不能把这个接口用来执行 shell、重启 Wi-Fi 或改变代理。启用选择不因重新连接而改变。

`backend/` 包含 Python 后台模块：`lte_helper.py` 由系统 LaunchDaemon 以 root 运行，保存启用选择并管理 `lte_auto.py`。`lte_auto.py` 结合物理接口可用性、HTTPS 探测与切换策略管理 `engine/` 中的 MBIM 引擎。模块的 USB 访问、临时 utun、接口计费标记及网络状态发布需要管理员权限。

构建阶段把后台模块和原生二进制暂存到 `build/runtime/`；安装后仍使用 `/Library/Application Support/MagicBayLTE/` 下的平铺布局。可执行代码安装在 root 所有且普通用户不可写的目录。源码分类不改变系统服务名称、安装位置或本地协议。

物理网络正常时只运行 control-only monitor，读取 SIM / 运营商 / 信号，并确认 session 0 已停用。无物理网络后才创建数据会话。返回物理网络时，先进入“切换中”，停止实际数据会话与接口，再验证新的出口，最后显示就绪。不能只改 UI 或把网络服务降为 Scoped，否则旧连接仍可能沿 LTE 传输。

`network_watch.c` 只读监听 SystemConfiguration 变化以唤醒检查。事件机制不可用时回退定时检查。`failover_policy.py` 设置故障 / 恢复确认窗口以抑制抖动。模块状态每 30 秒查询一次，手动信号按钮也复用现有控制会话，不额外抢占 USB。

1.4.1 同一观察器增加 IOKit USB 接入 / 移除通知，匹配 libusb 使用的 `IOUSBDevice` 兼容服务及 VID/PID，不绑定模块序列号。事件有递增代次，即使拔插后最终仍是“存在”，后台也会释放旧句柄再启动新会话。重新接入等待约 1 秒枚举稳定后尝试；失败从 2 秒重试，最长 30 秒，不延续此前几分钟的等待。无模块时不反复打开 USB。控制-only 待命会话若 75 秒收不到任何有效 MBIM 状态回复则重新打开；只是在搜网但仍能回复状态时不会触发此操作。活跃数据会话不使用这个状态查询超时看门狗。

不会主动关闭 Wi-Fi、重启网络服务、修改代理 / Clash / TUN 配置或发起自动断网测试。启用 LTE 表示允许在物理网络经检查不可用时自动使用移动流量。

本地日志及状态可能包含模块提供的运营商、IP 地址、时间等信息；它们不上传，且不属于公开仓库内容。日志目录为 root 所有、模式 `0700`，日志及运行状态文件使用 `0600`，另以 macOS ACL 向当前控制台用户授予只读访问；助手在控制台用户变化时更新访问权限。启用偏好不授予普通用户文件访问，只能通过受限控制协议修改。提交问题前请自行删去个人数据，不要上传整个运行目录。

`install_state.py` 统一安装与卸载的偏好策略：配置缺失为停用，升级保留有效的布尔选择，损坏配置拒绝启动或安装。卸载先确认服务与引擎退出，再保存停用选择并删除运行状态，避免重装时沿用旧的启用选择。`local_access.py` 负责文件权限与原子写入；源码和许可证保持可读，不授予普通用户后台目录写入权限。
